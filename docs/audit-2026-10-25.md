# CRooot SIGSYS 与原生轨迹双端修复（2026-10-25）

触发：report `46e765d534fb`，Project-Lumen `40f61ffc`，vivo V2426A / Android 16 / arm64；进程 `com.chloemlla.projectlumen:virtualization_probe`，seccomp 拦截 syscall 142（Linux arm64 `reboot`）。此前回复声称已改/推/CI绿，但实际没有修改，本次以实际 diff、提交与 Actions 为准。

## PL-S01：辅助 Application 重跑主进程初始化

- 文件：`app/src/main/java/com/projectlumen/app/ProjectLumenApplication.kt:233-279,290-328`。
- 类型：多进程生命周期边界 / 递归扫描。
- 症状：CRooot 的 regular 与 isolated service 启动时同样实例化 ProjectLumenApplication；attachBaseContext 安装完整 crash SDK，onCreate 初始化 MMKV、后台联网、凭据、设备控制、安全扫描。辅助进程重复启动 NativeRoot 检测，解释了 virtualization 进程内出现 KernelSU syscall 142 的路径，并使不同进程竞争同一个崩溃存储/历史标记。
- 改法：只在默认进程名且 Process.myUid() == applicationInfo.uid 时初始化宿主功能与 crash SDK，排除同名 isolated 进程，非主进程仅执行平台生命周期；onTrimMemory 也不得启动宿主采样。以可单测策略函数锁定默认进程边界。真实辅助进程异常仍由主进程 prior-exit 捕获，不按进程名删除/忽略退出记录。
- 状态：已修；本批提交后的 GitHub Actions 负责验证，真机复验仍待设备接入。

## PL-S02：protobuf 原生 tombstone 被误当 UTF-8

- 文件：`lumen-crash-core/src/main/java/com/chloemlla/lumen/crash/PriorExitCrashCollector.kt:76-89`。
- 类型：平台格式契约 / 二进制解码。
- 证据：AOSP ApplicationExitInfo.getTraceInputStream 文档明确 API31+ REASON_CRASH_NATIVE 返回 debuggerd/proto/tombstone.proto；现有 String(buffer, UTF_8) 导致报告出现二进制乱码。
- 改法：API31+ 原生崩溃按官方字段解码摘要与崩溃线程 backtrace；ANR/其他文本轨迹保持文本路径。解码器有输入/输出与集合上限，跳过未知字段、验证 wire type/length/varint，不把损坏或截断 protobuf 展示为乱码。新增离线 fixture 回归，由 GitHub Actions 跑。
- 状态：已修；本批提交后的 GitHub Actions 负责验证，真机复验仍待设备接入。

## PL-S04：fork 子进程 tombstone 可见性的旧注释不准确

- 文件：`DeviceSecurityGate.kt`、`DeviceSecurityScanner.kt`、`CroootFailureReporting.kt`、`ProjectLumenApplication.kt` 的错误上报说明；旧 `docs/audit-2026-09-26.md`。
- 证据：AOSP Android 16 `NativeTombstoneManager.collectTombstones()` 将同 UID 的 tombstone 转为 ApplicationExitInfo 并补入历史列表，未要求它原先是 AMS 托管进程。因此当前 prior-exit 报告不证明宿主主进程死亡，也不能再宣称 fork 子进程死亡绝对不可见。
- 改法：更正本链路源码注释；为旧审计补更正说明，不改当时观测记录。保留结构化非致命上报，覆盖不会生成 tombstone 的正常受限退出。
- 状态：已修；本批提交后的 GitHub Actions 负责验证，真机复验仍待设备接入。
